# Betweenly Frontend

Betweenly 的 React + TypeScript 前端，使用 Vite，开发端口固定为 **3000**。

参考 Koishi WebUI 的主题与工作区结构重新设计：单侧联系人列表、双栏记录与建议工作区，以及明暗主题。主题来源见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

## 启动

需要 Node.js 22.18+（测试使用原生 TypeScript 类型擦除）；已在本机 Node 24 上验证。

```powershell
cd frontend
npm ci
npm run dev
```

访问 `http://127.0.0.1:3000`。端口占用时会报错，不会静默切换到其他端口，避免与 Gateway 的 CORS 来源不一致。

```powershell
npm test
npm run build
npm run preview
```

产物位于 `dist/`。预览也使用 3000 端口，需要先停止开发服务。锁文件已保存，可用 `npm ci` 重现依赖。

## 页面与操作

- 左侧联系人列表：搜索、选择联系人，通过列表标题的加号新增；名称旁的铅笔按钮修改联系人，删除在右上角菜单内。
- 记录工作区：使用一个选择框切换聊天、事件和偏好；勾选记录后直接填写问题并查看建议。
- 图片：聊天记录的“＋ → 添加文字 / 图片”支持 JPG、PNG、WebP（原文件最大 8MB）。图片自动转为移除元数据的 JPEG，最长边不超过 1600px、单张不超过 256KB；可只保存图片、补充文字，或在编辑中更换/移除。点击缩略图预览，勾选图片记录后参与分析，每次最多 2 张。使用现有 DeepSeek 密钥，无须另配模型。
- 导入记录：聊天记录标题栏的导入图标提供“从微信导入”和“批量导入”。后者可粘贴“昵称 → 中文日期时间 → 正文”格式的文本，通过正则识别多条消息；确认各昵称对应的身份、勾选预览后导入当前联系人。支持多行正文、表情占位文字、日期后的多余空格和“时间未显示”，每批最多 1000 条；明确时间按北京时间解析，未知时间存为 null，不补填。单条最多 4000 字符，请求上限约 1 MB。相同批次重试不会重复写入；重新解析视为新批次。
- 微信导入：仅在用户自己电脑上的桌面版提供，网页端不显示入口，Vite 开发/预览代理也会拦截自动读取请求，避免局域网访客操作服务器电脑上的微信。网页使用批量粘贴导入。桌面版导入时，可能重复或未确认说话人的消息默认不选；同一预览提交可安全重试。
- 建议区：结果、回复、依据和待确认事项直接展示；文案可编辑复制，反馈和后续记录收在建议菜单内。
- 历史：使用联系人标题旁的历史图标打开，再次点击返回工作区。
- 设置：左下角齿轮打开，通过“连接与数据 / 表达习惯”页签切换，支持方向键、Home 和 End。
- Gateway：右上角绿色点表示连接成功，黄色表示连接中，红色表示失败；使用当前身份检查接口，5 秒超时，每 15 秒自动复查。
- 主题：左下角上方按钮切换明暗，下方为齿轮设置；窄屏通过顶栏按钮展开联系人列表。

页面不再使用统计卡片、多张任务入口卡片或重复操作入口；弹窗只保留必要的保存按钮。

## 登录与注册

网页版默认显示登录页，注册页通过 `#/register` 访问；普通用户登录成功进入 `#/workspace`，管理员进入 `#/admin`，两者共用登录入口。布局参考用户提供的 GalReview 前端：左侧品牌与标题、右侧表单。登录页和注册页均沿用参考的 11px 输入框及胶囊按钮圆角，工作区保留原有 12px 圆角。页面保持简洁文案、明暗主题及移动端布局，不增加第三方登录。登录页「忘记密码？」进入 `#/forgot-password`：先填写已验证的登录邮箱获取验证码，再输入验证码和新密码（6–128 字符）；保留相同的 11px 输入框圆角、胶囊按钮、明暗主题及窄屏布局。成功后返回登录并提示使用新密码，旧会话全部失效。

注册先输入邮箱并获取 6 位验证码（10 分钟有效，60 秒后可重发），再使用用户名、邮箱、密码（6–128 字符）、challengeId 和 verificationCode 提交到 `/api/v1/auth/registrations`；登录提交到 `/api/v1/auth/sessions`，支持邮箱或用户名，兼容已有密码。成功后读取 `/api/v1/auth/account`，使用 Bearer 令牌访问工作区。密码、访问令牌、刷新令牌均不写入 localStorage/sessionStorage，刷新页面需重新登录；访问令牌即将过期时串行轮换，刷新请求不自动重试。设置中显示当前账号，未验证的已有账号可验证邮箱，并提供退出登录，不向账号用户暴露开发身份输入框。

本地网页版使用独立账号后端（`scripts/start-accounts.ps1`，默认 Gateway `5088`）；Vite 默认代理到 `http://127.0.0.1:5088`。需要其他端口时，启动 Vite 前设置 `BETWEENLY_GATEWAY_URL`。桌面版继续使用原有本地身份进入工作区，不将本机数据绑定到新注册账号。此项没有重新打包或覆盖桌面 exe。

## 用户管理

服务端返回 ADMIN 角色后显示用户管理页，可按用户名/邮箱搜索、分页查看全部账号，点击「管理」打开用户资料弹窗，查看资料并重置密码；在弹窗内点击「账号管理」切换到二级视图，进行封禁、解封或删除。二级视图与返回资料均在同一个弹窗内完成，保留背景用户列表，切换使用轻微的滑动、淡入和高度过渡，并适配减少动画偏好。封禁时长可选 1 小时、1 天、3 天、7 天、30 天或永久；到期后服务端自动恢复登录权限，旧会话仍保持失效。删除有一次确认，采用软删除：账号从列表移除并禁止登录，保留历史数据和审计。当前管理员不能删除或封禁自身账号。顶部退出按钮显示「Log out」。管理员重置密码后，该用户全部旧会话和待用找回验证码失效；重置自己的密码后返回登录。用户密码不会以明文展示。普通账号无法通过直接访问页面或伪造角色调用管理 API。

## Gateway 接口

页面固定连接**真实 Gateway**，由 Python 服务调用 DeepSeek。设置不再提供模式选项，旧版演示模式设置自动迁移；测试用 DemoApi 仅作为契约夹具，未进入页面调用链。

Gateway 的默认配置：

```text
网页版 API 地址：同源 /api/v1 → 账号 Gateway http://127.0.0.1:5088
原本地 MVP Gateway：http://127.0.0.1:5080/api/v1
开发用户：7bc4918a-9079-4ea2-9e8e-369ad79a9f20（可更改）
```

开发 UUID 仅供 Gateway Development 环境联调。用户 Bearer 令牌仅保存在本次页面内存，刷新后清空。浏览器不会持有服务密钥，也不会访问 INTERNAL 接口。

接口遵循根目录 `contract.md`：

- 使用 `data/meta/traceId` 信封和分页游标；错误显示业务错误码及 traceId。
- 更新和受保护删除发送 `If-Match` 版本；分析创建使用 UUID 幂等键，同一输入失败重试保留原键。
- API 请求使用 100 秒前端超时，不自动跟随重定向，不发送 Cookie。
- 后端失败保留当前问题和草稿，不自动切换为演示建议。
- 聊天正文通过 React 文本渲染，不执行 HTML 或其中的指令。

业务服务与 Python DeepSeek 分析服务位于 `Backend/`，可通过根目录 `scripts/start-mvp.ps1` 一起启动；数据本地持久化。详细步骤见根目录 README。
